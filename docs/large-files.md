# 大文件首次打开实测

## 实测结果

测试使用改名前的 Viva Editor v0.32.1，环境为 Windows Build 26300、Intel Core Ultra 9 285H。样例位于本地 D 盘，每次用新的 Viva 进程和 WebView2 数据目录打开。以下包括一次初测与三次复测，容量以 MiB 计。

| 文件 | 样例规模 | 计时终点 | 四次耗时（秒） | 中位数（秒） |
| --- | --- | --- | --- | ---: |
| Excel `.xlsx` | 0.93 MiB、两个工作表、14.4 万个单元格，含 1.2 万条公式 | 首次单元格修改生效 | 6.44、1.37、1.43、1.41 | 1.42 |
| Word `.docx` | 8.50 MiB、72 个分页段、24 张图片 | 首次正文修改生效 | 1.31、1.28、1.31、1.31 | 1.31 |
| PDF `.pdf` | 17.10 MiB、120 页、48 张内嵌图片 | 首屏完成渲染 | 0.64、0.85、0.67、0.64 | 0.66 |
| JSON `.json` | 15.00 MiB、6.5 万条记录 | 首个输入字符进入源文 | 1.59、1.58、1.63、1.66 | 1.61 |
| HTML `.html` | 10.05 MiB、5.5 万个列表项 | 首个输入字符进入源码 | 0.236、0.227、0.224、0.224 | 0.226 |

Excel 初测出现一次 6.44 秒的等待，随后三次落在 1.37–1.43 秒。这个样例的压缩体积约 1 MiB，打开时仍要处理 14.4 万个单元格和公式。

## 测试口径

计时从 Windows 项目树点击消息发出开始。Excel 和 Word 进入就绪状态后，通过内嵌编辑器执行一次修改，并等到 Viva 收到修改事件。JSON 与 HTML 通过 Windows 文本输入消息插入一个字符，再核对缓冲区。HTML 使用默认分屏，记录源码可编辑的时刻，右侧网页继续独立加载。PDF 取首屏渲染完成事件。

样例由脚本生成，测量在独立 Windows 桌面运行。每轮启动新的应用进程并使用新的 WebView2 配置目录，Windows 文件缓存可跨轮复用。实际文档的公式、图片、分页和存储位置会影响耗时。

## 复测

```powershell
.\tools\large-open.ps1 -Runs 3
.\tools\large-open.ps1 -Formats xlsx -Runs 3
.\tools\large-open.ps1 -Formats html -Runs 4
```

命令将样例、单次日志和 `results.csv` 写入项目下的 `.dev/large-open-*`。每种格式都会使用真实的项目树入口。
